# Deploying Warmline

Postgres on DigitalOcean, the app on Render. About twenty minutes, most of it waiting
for the database to provision.

## 1. The database (DigitalOcean)

1. **Databases → Create Database Cluster → PostgreSQL** (version 17). The smallest shared
   node is plenty for one person.
2. Once it's up, open **Users & Databases** and add a database called `warmline`. You can
   use the default `doadmin` user.
3. **Connection Details → Connection string**, with "Public network" selected. It looks
   like:

   ```
   postgresql://doadmin:PASSWORD@db-postgresql-xxx.b.db.ondigitalocean.com:25060/warmline?sslmode=require
   ```

   Keep `?sslmode=require`. That encrypts the connection and needs no CA file, which is
   why no certificate appears anywhere in this repo.
4. **Trusted Sources**: DigitalOcean blocks everything by default. Once the Render
   service exists (step 2), add its outbound IPs here — Render lists them under the
   service's **Connect → Outbound** tab. Until you do, you'll see connection timeouts.

## 2. The web app (Render)

Push this repository to GitHub, then **New → Blueprint** and point Render at it.
`render.yaml` describes the service; Render will ask for the secrets it marks as
`sync: false`:

| Variable | What to put |
|---|---|
| `DATABASE_URL` | the connection string from step 1 |
| `APP_PASSCODE` | whatever you'll type to open the app |
| `BRIDGE_SHARED_SECRET` | a long random string; the bridge needs the same one |
| `AI_API_KEY` | your Gemma key ([AI Studio](https://aistudio.google.com/apikey)) |

`SESSION_SECRET` is generated by Render. Migrations run automatically in the
pre-deploy step (`prisma migrate deploy`), so the schema is in place before traffic
arrives.

A free instance works for a demo, but it sleeps after inactivity, so the first visit
after a quiet spell is slow. The `starter` plan in the blueprint avoids that.

## 3. The bridge — on your machine, or on Render

**On your machine (recommended).** Put the deployed URL in your local `.env` and run it:

```bash
WEB_API_URL="https://warmline-web.onrender.com"
BRIDGE_SHARED_SECRET="the same value you gave Render"
WA_FAKE=0
```

```bash
pnpm bridge
```

Messages are read on your own computer, only proposals travel, and it costs nothing.
The trade-off is that it only runs while your machine does.

**On Render.** Uncomment the worker block at the bottom of `render.yaml`. It builds
`apps/bridge/Dockerfile` (Puppeteer's image, so Chrome is already there and working) and
mounts a 1 GB disk at `/data` for the linked session.

Two things to know: disks are not available on free instances, and a service with a disk
runs as a single instance with a few seconds of downtime per deploy. Lose the disk and
you'll rescan the QR. Scan it from Warmline's own Settings screen — the bridge pushes the
code there, so you never need the worker's terminal.

## 4. Check it

1. Open the Render URL, sign in with `APP_PASSCODE`.
2. Type "Maya's birthday is on 14 June, she likes gardening" and save it — that exercises
   the database and Gemma in one go.
3. Open the event and press **Suggest how to prepare**.
4. If the bridge is running, Settings shows it as connected and lists your chats.

## When something's wrong

| Symptom | Cause |
|---|---|
| `Can't reach database server` | Render's outbound IPs aren't in DigitalOcean's Trusted Sources. |
| `self signed certificate in certificate chain` | `sslmode=require` is missing from the connection string. |
| Gemma errors with 400 or 429 | Wrong key, or the free tier's daily quota — check [aistudio.google.com/rate-limit](https://aistudio.google.com/rate-limit). |
| Bridge says it can't find a browser | Set `PUPPETEER_EXECUTABLE_PATH`, or run `pnpm chrome:install`. |
| Bridge connects but nothing appears | No chat is ticked in Settings. That's the consent gate doing its job. |
| QR scanned, then disconnects | The session folder isn't persisted. Use a disk (`WA_SESSION_DIR=/data/wa-session`). |

## Cost, honestly

The database is the floor (~$15/month on DigitalOcean's smallest cluster, or free on a
Postgres you already run). Render's starter web service is ~$7/month; free works for a
demo. The Render bridge worker adds ~$25/month with its disk, which is why running it on
your own machine is the default recommendation. Gemma on AI Studio's free tier costs
nothing but is rate-limited and, on that tier, your content may be used to improve
Google's products.
